# 多模型比较与模型融合

预测、分类及其他存在可替代学习器的任务，默认执行“至少三个非融合候选 + 至少一个融合模型”的同框比较。三个非融合候选中至少包含一个可解释基线，并尽量覆盖不同模型族，例如统计/线性、树模型、核方法或神经网络。数据规模、标签或计算条件不满足时，保留拒绝理由，不用低质量模型凑数量。

描述统计、确定性公式计算、纯机理求解和没有多个预测器的优化问题可以标为 `not_applicable`，但必须说明原因。若优化问题本身存在多种模型或算法，应比较基线启发式、数学规划/精确法和改进法；“模型融合”只有在能定义合法的解组合、集成决策或多场景策略时才使用。

## 统一比较

- 使用同一数据版本、目标、特征可得时点、训练/验证边界、预测跨度和评价指标。
- 时间序列使用滚动或前向验证；分类/回归使用分层或分组划分以匹配数据生成机制。
- 保存逐折、逐样本预测，而不只保存平均指标。比较主指标、至少一个辅助指标、跨折波动、最差折表现、运行成本和可解释性。
- 模型名称、配置、随机种子、失败状态和结果路径写入同一小问清单。
- 最终模型按事先声明的选择规则确定。融合未胜出也必须保留为 `benchmarked/rejected`，不得删除。

## 融合方式

优先使用可审计融合：

1. 等权平均：$\hat y_t^{ens}=M^{-1}\sum_{m=1}^{M}\hat y_{tm}$；适合样本较小、无法稳定估权的场景。
2. 约束加权：$\hat y_t^{ens}=\sum_m w_m\hat y_{tm}$，其中 $w_m\ge0$、$\sum_mw_m=1$；权重只能由训练期内部验证或先前滚动折确定。
3. Stacking：二层学习器只能读取严格样本外的一级模型预测；最终测试折不得参与二层训练。
4. 残差修正或专家门控：必须说明门控变量在预测时是否可得，并防止以未来状态选择专家。

分类任务应融合概率并校准，不只做多数投票；区间/分位数预测需要检查覆盖率和区间宽度。任何融合都至少包含两个有差异性的成员，列出成员、权重、权重来源、公式和泄漏控制。

## 采用规则

融合模型只有在相同样本外验证下满足下列至少一项时才进入最终方案：

- 主指标稳定优于最强单模型；
- 主指标基本持平，但跨折方差、最差折或业务风险显著改善；
- 下游决策的成本、缺货、违约或鲁棒性指标更好。

若融合被单模型稳定击败，应如实保留比较结果并选择单模型。论文应写“测试了融合但未采用”，而不是把融合本身当成创新。
