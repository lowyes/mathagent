# 交付前检查

## 结构与可追溯性

- 总清单覆盖所有问题和小问，编号与题面一致。
- 每个已完成小问的代码、图和结果均位于自己的目录。
- 公共代码有明确调用方，不包含题目输出。
- 每个核心数值都能追溯到结果文件、字段和生成代码。
- 每个跨小问输入都有字段、单位、粒度、质量标记和 fallback。
- 每个小问的建模契约含目标、非目标、验收标准与依赖。
- 对需要实验的任务，失败和不确定实验没有被删除，最终采用的每种计算方法都有通过的实验记录；确定性规则不伪造实验。
- 每个核心结论都指向真实结果文件及字段、行、键或工作表位置。
- 发现与决策日志保留关键限制、失败原因及其下游影响。

## 模型与计算

- 数据口径、缺失值、异常值和泄漏边界已说明。
- 符号先定义后使用，目标、约束、边界和量纲一致。
- 每种新方法均有核心公式或操作定义、符号、适用的参数来源链、执行步骤和输出字段。
- 每种方法均明确标记为核心或辅助并说明理由；全文至少识别一个核心方法。
- 声明 `flowchart` 的方法有真实存在的可编辑/可缩放流程图，内容与公式、代码和结果字段一致。
- 声明 `pseudocode` 的方法有带标题、行号、输入、输出和正文标签的伪代码；核心迭代算法同时具备二者，闭式公式和确定规则不被机械强制。
- 每个材料参数均标记为题面、上游、数据、文献、校准或情景来源；不存在“经验取合适值”等不可追踪表述。
- 跨问题参数注明上游文件、字段、单位、粒度、质量标记、转换公式和下游用途。
- 每个小问已声明文献门适用性与理由；`required` 的任务有经核验候选，`conditional/not_required` 没有被迫填充无关引用。
- 基线与改进模型采用相同数据划分和指标口径。
- 每个预测或分类小问在同一无泄漏划分、同一预测窗口和同一指标口径下，至少比较一个可靠基线和一个主要候选；额外模型对应真实待检验选择。只有成员性能合格、误差具有互补性且存在严格样本外成员预测时才测试融合，否则登记不采用原因。
- 固定并记录随机种子；启发式算法进行多次运行或精确对照。
- 检查可行性、物理/业务边界、残差或误差、敏感性与鲁棒性。
- 每一种验证评估方法都明确指向被验证的模型、参数、约束、结果或结论，并登记实际协议、判据、实验、证据文件与字段定位。
- 每一种验证评估方法都在正文所属小问中完成“简要定义—本题实施—实际结果—解释—决策影响”闭环，不存在与本题结果脱节的通用知识介绍。
- 对“精确、统计、仿真、启发式、fallback”的措辞准确。
- 每个新项目的小问已完成模型修订复核；若验证触发重建，已登记触发证据、失败诊断、真实修改、新旧实验和最终决定；若无需修订，已说明理由。
- 赛题分析、建模、计算三个质量门已通过。

## 论文与提交

- 每个小问有直接回答和至少一个能直接回答题目的核心结果载体；需要精确横向比较时使用结果表。
- 模型假设已与题面事实、计算口径、决策偏好和适用边界分开；每条实质假设说明对象、理由及失效影响。
- 全局符号表与核心公式完成双向核对：没有未定义、未使用或一符多义的符号，下标、维度、单位和取值域一致。
- 问题重述已通过题面覆盖矩阵反查：全部问题、小问、关键数字、单位、阈值、时间窗、不等号和提交要求均被准确覆盖，且未提前写入模型、求解过程或结果。
- 问题背景明显短于任务分解，没有与本题建模无关的领域史、政策口号、算法史或百科材料。
- 标题层级与题面问题、小问顺序一致；每个小问在连续章节内形成“任务—模型—结果—验证—回答”闭环。
- 每个核心结论均有 E3 级结果与验证证据，并能向前追溯到方法执行证据和原始数据审计证据；没有用模型原理替代实际结果。
- 已运行正文精炼扫描；模型历史、百科式定义和通用优点若不影响本题选择均已压缩，长段落与长句已经人工复核。
- 已人工复核精炼扫描中的工程术语、只报数字未作判断、本地路径泄漏和因果越界提示；项目清单语言没有直接进入正式论文，相关性与模型贡献没有被写成未经支持的因果结论。
- 已用首尾句反查法复核文章递进：任务产生选择标准，方法落实到结果，结果经过验证形成回答；表与图连续出现时已说明精确数值与趋势/结构的证据分工，图表后没有未经解释就跳入下一标题。
- 使用优秀范文时，Style Card 的共同特征均由至少两篇独立范文及页码支持；当前 PDF 已完成摘要、题面映射、模型引入、结果验证、段落/图表/跨问递进和最终版面的六维写后复核，差距与处理位置均有记录。
- 问题重述只界定任务，问题分析只说明困难与路线，模型建立只保留本题真正使用的数学结构，三者没有大段重复。
- `paper_profile` 已根据数据共享、任务差异和总结需要登记结构 Profile 与理由；假设/符号的合并或拆分、公共数据章、逐问题分析位置、模型评价章、`source_order` 和正式源文件链完全一致。公共数据型、问题独立型与混合型没有被混写；缺少实质内容的可选章节未生成。若采用官方/用户覆盖模式，已登记可定位依据且没有借覆盖模式掩盖普通结构错误。
- 问题分析按“任务—数据特征—关键困难—处理策略”组织，并依据小问共性位于顶层、小问内部或两者结合；标题使用研究动作而不是参数来源、证据定位等内部审计术语。全文无无理由的半空页，标题后至少保留两至三行正文。
- 跨页图表没有因 `[H]` 等强制定位制造明显空白，引出句或承接句没有孤立在上一页；允许浮动后，图表编号、首次引用和解释顺序仍清楚。
- 较长符号表能够自然移页或跨页并重复表头，没有为保持“每节独立”而造成断表或异常留白。
- 模型比较或消融段形成“实验设计—核心数字—横向比较—本题数据特征—模型取舍/边界”的证据链；普通结果段至少包含比较对象、真实数值、证据允许的解释或边界以及决策影响。实验只支持性能差异时不编造机制。
- 摘要只在全部小问完成、结果锁定后由 `placeholder` 切换为 `final`；每个问题均登记摘要证据文件与定位。
- 摘要按题面顺序设置“问题一：”或“针对问题一：”等独立粗体段落；全文选定一种形式并保持一致，每问均有任务、方法、关键结果和直接结论。
- 每张图有明确用途、正确路径、中文标签和正文解释；记录分析问题、绘图库及版本、选择理由和源脚本，可选库缺失时的回退有据可查；文件签名、结尾标记和非空性检查通过，不存在改后缀伪图或损坏图。
- 已声明的方法流程图紧邻对应方法段落并被正文引用；源文件位于所属小问代码目录，渲染文件位于图目录，打印后文字与箭头仍清晰。
- 已声明的方法伪代码位于最有利于理解执行逻辑的位置；只包含真实循环、分支、终止与 fallback，不虚构结构，也不粘贴语言相关实现代码。
- 每条验证评估记录的正文标签真实存在，结果表或图紧邻被验证对象，正文说明结果如何支持、否定或限定模型与结论。
- 模型评价中的每项优势和局限均有证据；每项局限都有对应改进方向，已实现改进与未来工作没有混写；推广场景说明了共享数学结构、变化假设和重新验证要求。
- 引用与参考文献双向对应且来源真实。
- schema v3 项目的正文引用键、`citation_ledger` 与 `\bibitem`/`.bib` 定义完全对应；核心主张未使用博客、论坛等 `discovery_only` 来源作为唯一依据。
- 匿名正文无身份、路径、API 或调试信息泄漏。
- 编译报告来自当前两遍 XeLaTeX 编译，输入源文件和 PDF 哈希均与当前文件一致；旧报告不能替代重新编译。
- PDF 无缺字、溢出、重叠、断表、空白异常或未解析引用，视觉检查记录绑定当前 PDF 哈希。
- 当届官方封面、页数、文件名、附件及 AI 声明要求已核对。
- 最终校验使用 `--final`，论文质量门已在PDF视觉检查后通过。
