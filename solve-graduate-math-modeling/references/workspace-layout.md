# 工作区与文件归属

## 目录结构

```text
项目/
├── 题目/                         # 原始赛题，只读保留
├── 数据/                         # 原始附件，只读保留
├── 项目清单.json                 # 问题/小问、依赖与交接总表
├── 求解计划.md
├── 求解/
│   ├── 公共/
│   │   └── 代码/                 # 仅放真正复用的函数或模块
│   ├── 问题一/
│   │   ├── 小问1/
│   │   │   ├── 代码/
│   │   │   ├── 图/
│   │   │   ├── 结果/
│   │   │   └── 小问清单.json
│   │   └── 小问2/ ...
│   └── 问题二/ ...
├── 论文/
│   ├── main.tex
│   ├── graduate-modeling.cls
│   └── 章节/
└── 交付/                         # 最终 PDF、附件和提交清单
```

## 归属规则

代码、图和结果以“产生该证据的小问”为唯一归属单位。一个文件不得同时归属于两个小问；确需跨小问使用时，保留单一源文件，并由下游小问通过交接契约读取。

公共目录只接收不含具体题目结果的复用代码。数据清洗脚本若只服务于问题一小问1，仍放在该小问的代码目录。全题统一的数据字典、解析器或通用绘图样式可以放公共代码目录。

每个 `小问清单.json` 至少维护：建模契约、算法与参数血缘、实验记录、发现与决策、结论—证据矩阵、四阶段质量门、目标输出、单位、输入、依赖、代码文件、图文件、结果文件、核心指标、随机种子、运行状态、验证状态和直接结论。路径一律相对于项目根目录。详细字段见 [evidence-workflow.md](evidence-workflow.md)。

## 跨小问交接

下游小问使用上游输出时，在总清单中记录：

- 提供方和使用方；
- 文件与字段名；
- 单位、时间/空间粒度；
- 缺失值和质量标记；
- 版本或生成时间；
- 不满足质量门槛时的 fallback。

禁止下游静默重算一个口径不同的同名指标。

## 图表路径

从 `论文/` 目录编译 `main.tex` 时，即使图片命令写在被引入的章节文件中，路径仍相对于主编译目录。引用示例为：

```latex
\includegraphics[width=0.82\textwidth]{../求解/问题一/小问1/图/误差分布.pdf}
```

不要把图片复制进论文目录来掩盖归属关系。
