# 核心算法流程图

仅当方法在 `representations` 中声明 `flowchart` 时应用本规范。核心方法并不自动等于必须画流程图；闭式公式、确定性规则或单步统计检验通常无需用图重复。多阶段、分支、循环、回退或跨模块管线应声明并遵循本规范。

## 1. 识别核心方法并决定是否需要流程图

在完成候选比较、确定论文主线后统一判断。满足下列任一条件的最终采用算法通常应标为核心：

- 直接产生摘要或结论中的关键数值、预测、排序、方案或决策；
- 构成主要改进、创新点或相对于基线的关键增量；
- 包含多阶段计算、重要分支、迭代、反馈、收敛或可行性修复；
- 输出被多个后续问题消费，错误会改变全文结论。

全文通常保留 1--3 个核心方法。数据读取、常规清洗、单个统计量和仅作对照的候选模型一般标为辅助方法。核心性与表达载体是两项判断：核心方法若没有多阶段、分支、循环或回退结构，可以只用公式/定义和结果证据；不得为逃避必要绘图而隐去真实复杂管线，也不得把所有步骤都标为核心以堆叠图片。

## 2. 流程图必含内容

每个声明 `flowchart` 的方法至少用一张图表达真实执行链：

1. 输入数据或上游字段、粒度和必要单位；
2. 关键预处理、初始化或参数载入；
3. 与正文核心公式对应的计算模块；
4. 真实存在的判断、循环、模型选择或约束检查；
5. 停止条件、不可行处理、异常分支或 fallback；
6. 输出字段、结果文件以及下游用途。

判断节点写成可回答的是/否问题，回路箭头必须返回实际迭代位置。节点名称使用正文术语，避免“数据处理”“运行算法”“得到结果”等无法审计的空泛表述。若算法没有分支或循环，使用简洁顺序图，不得虚构复杂性。

## 3. 与论文和实现保持一致

- 图中的每个主要计算块能对应正文公式、伪代码步骤或代码函数。
- 图中的参数不得出现于参数来源表之外；图中的输出名称与结果文件字段一致。
- 图不能替代核心公式、符号定义、参数来源链和文字求解步骤。
- 多个核心算法只有在构成不可拆分的同一管线时才共用一张图；用泳道、分组框或明确边界区分算法，并让各算法记录指向同一文件。

## 4. 制作、归档与排版

优先输出矢量 PDF 或 SVG，可使用 Graphviz、TikZ、Matplotlib、MATLAB 或其他可复现工具。将源脚本放在所属小问的 `代码/`，将最终图放在 `图/`，并把渲染文件登记到 `figure_files`。使用中文节点、方向一致的箭头、统一形状语义和黑白打印可辨的颜色；避免交叉线、过密文字和截图式低清图。

流程图与伪代码不固定先后顺序。总体技术路线图通常紧跟问题分析，用于在数学模型前建立阅读地图；核心执行流程图放在相应算法的数学结构、参数或求解过程附近。选择能减少重复并保持证据链连续的位置。正文在图前交代阅读目的，在图后解释关键分支、循环、终止条件和输出去向。

## 5. 清单字段

声明流程图的方法在通用方法记录上追加三个流程图字段：

```json
{
  "name": "约束加权融合模型",
  "purpose": "在问题二给出最终日频预测",
  "formula_reference": "正文式(12)",
  "parameters": [
    {
      "symbol": "w_m",
      "value_or_rule": "非负且和为1，由训练期内部验证求解",
      "unit": "无量纲",
      "source_type": "calibration",
      "source": "求解/问题二/小问1/结果/权重标定.csv",
      "downstream_use": "加权成员预测得到融合值"
    }
  ],
  "is_core": true,
  "core_reason": "生成最终预测并向问题三输出关键字段",
  "flowchart_source": "求解/问题二/小问1/代码/绘制约束加权融合流程图.py",
  "flowchart_file": "求解/问题二/小问1/图/约束加权融合流程图.pdf",
  "flowchart_reference": "正文图6"
}
```

新版清单还需在 `representations` 中登记 `flowchart`。`name`、`purpose`、`is_core`、`core_reason` 以及 `formula_reference` 或 `definition_reference` 对每种方法必填；`parameters` 是否非空由 `parameter_applicability` 决定。旧版 `algorithms` 仍按原字段兼容。参数记录要求见 [algorithm-parameter-lineage.md](algorithm-parameter-lineage.md)，最终以 `scripts/validate_project.py` 为准。

未声明 `flowchart` 的方法将三个流程图字段留空。已声明方法的 `flowchart_source` 必须真实存在、属于同一小问的代码目录并登记在 `code_files` 中；`flowchart_file` 必须真实存在、属于同一小问的图目录并登记在 `figure_files` 中；正文由 `flowchart_reference` 指向该图。
