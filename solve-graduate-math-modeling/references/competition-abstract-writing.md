# 数学建模竞赛摘要：证据、自然表达与版面

## 适用时机

只在结果锁定后写正式摘要。若用户提供优秀论文作为语言参考，先阅读其摘要的页面布局与行文方式，提炼结构和节奏，不复制原句、专有内容或数值。

## 写作目标

摘要要让评委快速找到三件事：每问做了什么、得到什么、结论是什么。真实性和可核验性优先于辞藻。自然表达不是故意口语化，也不是规避检测器，而是减少模板套话，让句子服从实际推理顺序。

## 推荐组织

1. 开头用一个自然段说明现实背景、数据难点与本文要解决的核心矛盾。若数据划分会影响可信度，可在此交代样本单位和防泄漏口径。
2. 按题面顺序写问题段。默认每个顶层问题以粗体“针对问题一：”等开头；段内沿着“处理原因—实际步骤—关键结果—结论”推进。
3. 小问很多时可把同一问题拆成相邻的两个自然段，不必把全部内容塞进一个超长句。
4. 结尾总结可省略。若正文已经在最后一个问题段给出最终方案和适用条件，不再追加空泛的“综上所述”。
5. 关键词通常取3–6个，覆盖研究对象、核心模型和决策口径。

## 用户限定摘要范围

默认摘要覆盖全部顶层问题。当用户或比赛模板明确要求只写部分问题时，服从该范围，不用隐藏文字或无内容标签迎合校验器。此时在 `项目清单.json.paper_workflow` 中登记：

```json
{
  "abstract_questions": [1, 2, 3],
  "abstract_scope_reason": "用户明确要求摘要仅保留前三问"
}
```

`abstract_questions` 省略或为空数组表示覆盖全部顶层问题。只为摘要实际覆盖的问题登记和检查 `abstract_evidence`；正文题目仍须完整，除非用户另有要求。

## 降低模板化语言

- 多写真实动作和对象，例如“按病灶分组”“枚举权重”“锁定测试集”，少写“构建完整体系”“有机结合”“全面赋能”。
- 模型名后紧跟它解决的具体问题，不连续罗列算法名。
- 数值嵌入推理：先说明为什么比较，再给结果，最后说明结果改变了什么选择。
- 允许长短句交替。一个句子只承担一个主要判断；并列步骤过多时拆句。
- 避免每段都以“首先—其次—最后”“结果表明—综上所述”收束。可用“比较后选择……”“由此可见……”“因此……”等与证据直接相连的表达。
- 不夸大。把“显著优于”改为有基准和幅度的陈述；没有统计检验时不用“显著”。
- 不声称能够保证通过任何AI文本检测。只能说明已减少重复句式、空泛评价和不必要的抽象名词。

## 结果取舍

- 每问保留能直接回答题目的核心指标、方案、排序、区间或误差；模型内部参数只保留对结论有决定作用的少数项。
- 多层融合、阈值或校准同时出现时，说明每组参数属于哪一层、来自训练数据统计还是验证集选择，并明确测试集是否参与。
- 对准确率、召回率等存在取舍的结果分别报告适用场景，不把两套决策口径混成一个“最佳结果”。
- 摘要中的每个关键数值必须能回到结果文件和字段定位。

## 一至两页的版面处理

先服从当届规则和用户要求。没有硬性限制时，通常使用一至两页：

- 一页能完整表达时不要为凑两页扩写。
- 两页时在问题边界处分页，优先让第二页从一个完整问题开始；不要只把结论或关键词挤到第二页。
- 编译后渲染摘要全部页面，检查标题、段落间距、页码、孤行和大面积不均衡留白。
- 若自动分页只溢出数行，先压缩重复内容；若用户允许两页且某一问题内容较长，可在该问题前显式分页以保持语义完整。

## 交付前自检

- 摘要范围是否符合题面、模板和用户明确要求？
- 每个纳入摘要的问题是否都有方法、真实结果和直接结论？
- 是否出现正文没有的模型、数值或因果解释？
- 是否清楚区分训练、验证和测试用途？
- 是否存在套话、重复判断、过度形容或无统计依据的“显著”？
- 最新PDF的摘要页面是否经过逐页视觉检查？
