# 研究生数学建模论文写作

## 匿名与官方材料

正文不得出现学校、队员姓名、队号、联系方式、本地路径、API 配置或内部运行日志。官方封面、承诺书、文件命名、附件格式、页数限制和 AI 使用说明每年可能变化，必须以当届通知为准。官方封面与匿名正文分开维护。

## 章节结构

章节选择以 [competition-paper-structure-evidence.md](competition-paper-structure-evidence.md) 为唯一权威，本文件不维护第二套固定目录。初始化前根据数据共享关系选择公共数据型、问题独立型或混合型 Profile，再独立决定假设与符号合并/拆分、各问题分析的位置以及是否需要统一模型评价章。正式结构、理由与 `source_order` 同时登记在 `paper_profile`；不得只改正文而保留旧结构记录。

问题重述按 [competition-problem-restatement.md](competition-problem-restatement.md) 执行。通常采用“短问题背景＋按题面顺序的问题提出”，并在写作前建立题面覆盖矩阵。背景不扩写成领域科普；任务段保留所有会改变答案的对象、数字、单位、阈值、时间窗、不等号和提交要求，但不提前出现模型、算法步骤或计算结果。

模型假设、计算口径和符号说明按 [competition-assumptions-symbols.md](competition-assumptions-symbols.md) 执行。先把陈述区分为题面事实、模型假设、计算口径、决策偏好和适用边界，不能全部放进“假设”编号。符号总表只保留跨公式复用或需要说明维度、下标、单位和取值域的符号；局部符号在公式旁定义。

### 前置章节连续排版

摘要、目录和正文入口是否分页服从官方模板。正文开始后，“问题重述—假设与符号（合并或拆分）—可选公共数据章节”默认连续编排，不要求每节另起一页；问题分析依任务共性放在顶层问题、小问内部或两者结合。

- 不在这些短章节或对应的 `\input` 之间无理由插入 `\newpage`、`\clearpage` 或 `\pagebreak`；让 LaTeX 根据剩余空间自然分页。
- 若标题落在页底而后文不足两至三行，优先调整标题前后的间距或使用防孤立标题机制，不把所有同级章节统一改成强制换页。
- 符号表较长时使用可自然跨页并重复表头的表格环境；允许表格因空间不足自然移至下一页，不为追求“每节独立”制造半空页。
- 图表组合跨页时，检查引出句、承接句和解释段是否与对应证据保持在可连续阅读的位置。若 `[H]` 造成明显半空页或把承接句单独留在上一页，优先改用 `[htbp]`、调整图幅或重组图表顺序；不要用强制分页掩盖浮动体问题。
- 只有当届模板明确规定、用户明确要求，或 PDF 视觉检查发现孤立标题、断表等实际缺陷时，才对具体位置设置分页。

每个小问内部保持“任务边界—数据与假设—数学表达—求解过程—结果表—验证—直接回答”的相邻闭环。它们是内部完整性检查项，不是七个固定标题；简单小问可用一个自然小节完成。标题跟随真实研究动作，不把 JSON 审计字段搬进目录。不要把全部验证集中到最后一章。

先按 [competition-paper-structure-evidence.md](competition-paper-structure-evidence.md) 建立章节和证据链，再在起草或压缩正文时读取 [competition-paper-prose.md](competition-paper-prose.md)。结构与证据组织优先于语言模仿。问题重述、问题分析和模型建立承担不同职责：问题重述界定输入输出，问题分析说明困难与路线，模型建立给出本题实例化的数学结构。不得在三处重复同一段题意、数据介绍或方法流程。

竞赛论文不以算法史和通用知识展示篇幅。常见基线原则上只保留选择依据、理解实现所需的核心公式及参数来源；核心创新才展开结构、伪代码、流程图和受控验证。介绍任何理论后，应能立即回答“它在本题中对应哪个输入、参数、步骤或结果”；不能回答的内容优先删除。

验证与评估内容必须回到被验证对象：先指出要验证哪个模型、参数、约束、结果或结论，再给出方法定义与本题实施协议，随后展示真实结果、解释含义并说明它对最终选择或结论边界的影响。不要复制一段通用的“交叉验证介绍”“混淆矩阵介绍”或“误差指标介绍”后与本题结果断开。

## 摘要

摘要最后写。正文阶段只保留 `% ABSTRACT_STATUS: placeholder`，不得提前填写带结论和数值的“临时正式摘要”。只有所有小问状态为 `complete`、计算质量门通过、核心结果与结论证据锁定后，才执行以下步骤：

1. 在 `项目清单.json.paper_workflow` 中把 `results_locked` 设为 `true`。
2. 默认覆盖全部顶层问题；若用户或官方模板明确限定摘要范围，登记 `abstract_questions` 和 `abstract_scope_reason`。为范围内每个问题登记一条 `abstract_evidence`，写明摘要关键数字对应的结果文件和字段/键/行定位。
3. 按 [competition-abstract-writing.md](competition-abstract-writing.md) 建立 `abstract_plan`：先判断该问是否继承上游、具体修改了什么，再分别锁定任务、核心方法、关键结果和直接答案；模型亮点通过资格门时才登记，否则明确为 `not_applicable`。
4. 根据规划写摘要并逐问反查证据，将 `abstract_evidence_check` 设为 `passed`。规划字段用于内部决策，不直接变成固定段落标题或五句模板。
5. 最后把摘要文件标记和 `abstract_status` 同时改为 `final`，再编译、视觉检查并执行 `validate_project.py --final`。

正式摘要采用便于评委逐题核对的结构。下列各条只说明摘要在全文中的位置和证据要求；段落组织、关键词数量、语言风格与一至两页分页以 [competition-abstract-writing.md](competition-abstract-writing.md) 为准，写摘要时必须同时读取该文件：

1. 通常用1--3句说明背景、总目标和总体技术路线，不展开数据清洗过程。
2. 随后严格按声明的摘要范围和题面顺序，每个问题单独成段。粗体标签可用“问题一：”或“针对问题一：”，全文选定一种并保持一致；默认范围是全部顶层问题，只有用户或官方模板明确限定时才可缩小。不得用“首先、其次、再次、最后”把多个问题合并成一个段落。
3. 每个问题段按“题目要求 → 核心方法/模型 → 已审计关键结果 → 直接结论”形成证据链；这不是固定四句模板。后续问题若继承前问，先说明保留与新增内容及其造成的新困难，再只写增量模型。若问题含(a)(b)(c)等小问，在同一问题段内按小问顺序逐一覆盖；内容较多时可拆成连续的两个段落，但问题标签和小问对应关系必须清楚。
4. 结果优先给出能直接回答题目的数量、区间、排序、方案、误差或可行率。只写“建立了模型”“进行了分析”“效果较好”不算回答。
5. 模型比较只保留最终选择依据和核心指标，不在摘要堆叠全部参数、公式、图表编号、代码过程或文献综述。
6. 最后一段可概括经证据支持的模型设计、鲁棒性、适用边界或推广价值；没有增量信息时省略。算法名称本身不是创新，限制条件也不能替代任何一道问题的直接答案。
7. 结尾给出能代表研究对象、核心模型和数学机制的关键词，默认4--6个，官方要求优先。

摘要中的模型名、数值、单位和结论必须从最终结果表复制并复核。通常控制为1–2页，但当届规则优先，不预设永久页数。完成后对范围内问题逐一反查：是否能仅凭摘要找到“用了什么、得到了什么、说明什么”。

## 图表和公式

每张核心表和图都必须在正文中引用，并至少说明它支持哪个分析判断。机制或局限只在证据支持或确有必要时说明；不得为凑齐固定句式编造原因。模型比较和消融尽量保持“实验设计—核心数字—横向比较—本题数据特征—模型取舍”与对应表图连续出现。表格呈现关键数值，图形呈现结构、趋势或关系；避免同一证据重复作图。

表和图可以连续出现，但必须能够回答“为什么两者都需要”。同一结果同时采用表和图时，在首次引出处说明证据分工：表用于精确核对数值，图用于观察趋势、结构、误差或不确定性。若这层分工已在前文明确，表图之间不强制插入套话；若没有明确，增加一句承上启下的实质说明。最后一个图表之后仍需完成“观察结果—支持的判断—对模型选择或题目答案的影响”，不得以图题作为一节的结论。

排版目标是“信息密度高但层次清楚”：表题置于表上，图题置于图下，公式居中并按需编号；图表尽量靠近首次引用和解释，不让核心表与取舍结论相隔数页。流程图按论文信息图控制字号、节点与留白，除非结构确实复杂，不为追求视觉冲击占满整页。一级标题保持克制，不使用咨询报告式大色块、装饰边框或无分析意义的大面积留白。

公式先定义符号再使用，文字解释各项现实含义，并在完整模型后说明算法为什么适合变量规模、约束结构和数据质量。不得为增加篇幅强制堆叠公式。

每种方法首次出现时紧接必要的定义/公式和参数来源；没有待估参数的方法明确说明口径即可，不强制参数表。需要参数表时正文通常只展示“符号、含义、取值/单位、确定依据”，完整来源类型、文件字段、转换和下游用途保留在小问清单；关键上游参数仍需在正文明确写出字段与转换。

当核心方法包含多阶段、分支、循环或回退路径时配流程图。流程图表达整体结构，伪代码表达精确执行，二者不得重复，也不固定先后顺序；闭式公式、确定性规则或一步检验不为形式完整强制加图。声明流程图的方法必须展示真实执行链，不加入代码中不存在的装饰步骤。

当方法含迭代、搜索、递推或非显然执行逻辑时给出带行号的伪代码。核心迭代算法同时需要流程图与伪代码；其他方法按增量信息选择。伪代码使用数学符号和自然语言描述真实输入、输出、循环、判断、终止/fallback 与返回值，不粘贴 Python、MATLAB 或求解器 API。

每种验证评估方法首次出现时只解释理解当前结果所需的概念。指标公式必须定义符号、方向和适用口径；数据划分必须说明样本单位、分层/分组/时间顺序和泄漏控制；敏感性、鲁棒性、仿真或优化验证必须说明扰动范围、基准情景、重复次数、可行性或收敛判据。紧接着给出本题结果表或图，并用“结果是什么—说明什么—因此如何决策”的顺序解释。

## 参考文献与外部材料

只使用真实、可核验且正文实际引用的文献。方法首次使用处引用原始或权威来源；外部事实引用数据或官方来源。公开程序、开源代码、网络材料和 AI 辅助内容按当届规则披露，不得冒充原创。

schema v3 项目在 `paper_workflow.citation_ledger` 登记正式进入正文的外部主张，并按 [literature-algorithm-screening.md](literature-algorithm-screening.md) 区分来源类型与权威性。最终交付时正文引用键、引用台账和参考文献定义必须双向一致；博客或论坛只能作为发现线索，不能单独支撑核心方法、参数或结论。参考文献著录格式服从当届官方规范，不把某一种示例格式永久固定为唯一标准。

模型评价按 [validation-evaluation-integration.md](validation-evaluation-integration.md) 建立“证据优势—局限及影响—对应改进—有条件推广”关系。已实现改进与未来设想必须明确区分；推广必须说明共享数学结构、变化假设和重新验证要求。评价内容可就地进入各问题，也可在确有汇总价值时形成独立章节。

## 正文精炼检查

用户提供优秀范文时，先按 [competition-style-transfer.md](competition-style-transfer.md) 生成 `论文/style-card.md`，再结合当前项目证据写作。Style Card 只迁移方法引入、结果节奏、承接方式和标题粒度，不迁移范文模型、数字、假设、结论或原句。

正文完成后运行 `python scripts/audit_paper_prose.py <论文目录>`，逐条处理长段落、百科式定义、算法历史、模糊效果评价、过密连接词以及图表递进断点提示。随后按 [competition-paper-prose.md](competition-paper-prose.md) 的“首尾句反查法”检查章、节、段落和图表之间是否形成真实推理链。脚本只提供定位，最终取舍以本题推理与证据完整性为准。删除或合并文字后必须重新编译并检查标题、公式、表图引用、孤行和版面留白。

## LaTeX 模板

模板正文采用 A4、中文、匿名正文、一级标题居中和页脚居中页码的通用研究生赛样式。它不是当届官方封面。若官方格式与模板冲突，修改模板以服从官方要求。

模板资源和生成后的章节源文件统一使用 ASCII 文件名，中文只出现在论文标题中，避免 ZIP 或跨平台工具破坏路径。页码可用类选项 `bodyresetnumbers` 或 `continuousnumbers` 选择；当届规则优先。

`compile_paper.py` 使用 XeLaTeX 两遍编译并通过 recorder 记录当前输入哈希。任何正文、类文件、参考文献或被引用图表发生变化后都必须重新编译。人工检查最终 PDF 后，在 `paper_workflow.pdf_visual_review` 中登记 `status: passed`、当前 `pdf_sha256` 和实际检查项；旧 PDF 的检查记录不得沿用。

编译器解析顺序为：显式 `--compiler`、当前 `PATH`、`TEXLIVE_BIN/TEXLIVE_ROOT`、`C:`/`D:` 常见 TeX Live 目录、常见 MiKTeX 目录。编译报告中的 `engine_path` 与 `engine_resolution` 必须反映实际使用的可执行文件；不得仅因当前终端尚未刷新 PATH 就降级为伪造编译记录。
