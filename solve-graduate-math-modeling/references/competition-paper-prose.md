# 数学建模竞赛正文：精炼、证据化与去百科化

## 使用边界

在起草或压缩问题重述、问题分析、模型建立、结果分析和模型评价时读取本文件。优秀论文仅用于观察章节组织、证据节奏和版面密度；用户提供范文时，先按 [competition-style-transfer.md](competition-style-transfer.md) 生成项目 Style Card，再将它与当前项目证据一起交给写作过程。不要复制范文原句、具体模型组合、数值、图表或未经核验的行业背景。获奖论文也可能存在长背景、教材式定义或指标使用不严谨的问题，应取其结构长处而不是整篇模仿。

## 竞赛正文的核心任务

竞赛论文不是算法百科，也不是文献综述。评委阅读每个小问时，应能连续找到：

1. 题目要求输出什么；
2. 数据或约束造成什么困难；
3. 为什么选择当前方法；
4. 模型如何在本题上被实例化；
5. 结果是多少；
6. 结果是否可信、最终回答是什么。

一个段落至少承担“任务、方法、证据、解释、边界”中的一项。若整段只介绍模型历史、通用优点或宏观意义，删除或压缩。

## 各章节的职责

### 问题重述

- 背景通常控制为一至两个自然段，只保留理解任务边界所需的信息。
- 不从搜索资料扩写疾病史、产业史或算法发展史；外部事实若不是后续模型输入、约束或评价依据，不进入正文。
- 按题面顺序重述输入、输出和小问关系，不提前写求解结果，也不逐句改写题目。

### 问题分析

- 不重复问题重述。优先按“具体任务—数据特征—关键困难—处理策略—上下游依赖”展开，不以算法名称作为起点。分析结束后，读者应能自然预期后续为什么需要相应的数据处理或模型。
- 优先指出泄漏、缺失、不平衡、时序、量纲、约束、评价口径等会改变模型选择的因素。
- 一张总体流程图可代替重复的步骤叙述；图后只解释关键分支和数据流。
- 小问共享困难和路线时在顶层统一分析；任务性质明显不同时在各小问内部分析；存在共同主线和局部新增困难时两层结合，但不重复同一句困难。

### 模型建立

先写选择依据，再写数学结构。推荐顺序为：

> 本题困难或数据特征 → 候选方法需要具备的能力 → 选择当前模型的理由 → 本题中的输入、输出和参数 → 核心公式 → 求解协议。

模型介绍不得以“某模型由某人在某年提出”开场，除非提出时间或版本本身影响复现。不要写“是一种广泛应用的方法”“具有较好的性能”等无法支持本题选择的通用评价。

### 结果与验证

模型比较或消融段常用“实验设计—核心数字—横向比较—结合本题已审计的数据特征—模型取舍或边界”的次序。普通结果段可压缩为“比较对象—关键数字—变化幅度—证据允许的解释或边界—决策影响”。表图、实验说明和选择文字应尽量位于连续阅读区域。若当前实验只能支持性能差异，不得为了完整句式编造机制解释。例如：

> 在相同病灶级划分下，加入BiFPN后验证集Accuracy由0.831升至0.838，综合指标J由0.685升至0.701。因此多尺度融合得到保留；但B2在224像素下退化，说明扩大骨干不能脱离输入分辨率单独判断。

没有统计检验时不用“显著”。不要以“效果较好”“验证了可行性”替代真实指标、区间或约束满足情况。

## 文章递进关系审计

递进不是增加“首先、其次、因此”等连接词，而是让后一部分确实使用前一部分已经建立的对象、结果或判断。完成一章后，从以下四个尺度反向检查：

1. **章级递进**：前一问输出了什么字段、单位和结论；后一问保留了什么、新增了什么条件、由此产生什么新困难，并为什么需要新的模型或约束。
2. **节级递进**：任务和数据困难先产生选择标准，选择标准再引出模型；公式和参数落实该模型，求解结果随后接受验证并形成直接回答。不得从题目要求直接跳到算法名称，也不得从公式直接跳到结论。
3. **段间递进**：前一段末句应留下下一段真正需要的判断或对象，后一段首句说明承接、转折、细化或验证关系。若调换两个自然段而论证仍完全不受影响，通常说明段落只是并列堆放，尚未形成推理链。
4. **图表递进**：图表前说明为什么需要该证据，图表后说明观察结果及其决策影响。同一结果同时用表和图时，表承担精确数值，图承担趋势、结构或不确定性；若前文已一次说明二者分工，可以紧邻排版，否则在两者之间补一句真实承接。不要用“见下图”代替证据分工。

推荐用“首尾句反查法”复核每一节：只读标题、每段首句和末句、图表题注及小结，检查是否仍能恢复以下链条：

```text
题目要求
  → 数据事实或约束
  → 建模困难与选择标准
  → 模型、参数及求解
  → 表图或数值结果
  → 比较、验证与取舍
  → 直接回答及适用边界
```

缺少箭头时补的是实质信息，而不是套话。例如，“表3给出逐日预测值与区间；为观察变化趋势和区间宽度，进一步绘制图3”说明了表与图的分工；单写“由此得到图3”没有增加推理信息。

运行 `audit_paper_prose.py` 时，`adjacent_table_figure_without_bridge` 表示表与图直接相邻，`evidence_block_without_followup` 表示图表后直接进入新标题。两者都是人工复核提示而非自动错误：若前文已明确图表分工或已经完成解释，可保留紧凑排版；否则补充承接、分析或删除重复证据。

### 从工程证据到论文论证

项目清单负责可追溯，正文负责让评委理解。写作时先从结果文件提取事实，再完成“结果是什么—它支持或否定什么判断—因此怎样选择—边界在哪里”的转换；不得把内部字段名和运行口令直接抄入论文。

常见转换包括：“数据审计”改为“数据完整性与一致性检查”，“锁定模型”改为“确定最终模型”，“读取上游结果”改为“采用前一问所得结果”，“下游消费者”改为“后续问题使用”。`manifest`、质量门、文件哈希和本地路径仅留在内部记录，除非比赛要求披露复现信息。

结果段可以只报告数字，也可以讨论机制，但二者证据强度不同。若实验只显示性能变化，就讨论模型取舍和适用边界；只有机理方程、受控实验、稳健统计设计或可靠外部证据支持时，才把相关或特征贡献提升为因果解释。运行 `audit_paper_prose.py` 后，重点人工复核 `result_without_interpretation`、`internal_engineering_jargon`、`local_path_leak` 与 `causal_overreach` 提示。

## 算法介绍篇幅门

算法原理只保留理解本题实现和创新所必需的内容：

- 基线或常见算法：通常用一个选择依据段、一条核心公式和一个参数来源段即可。
- 只参与候选比较但未被采用的成熟算法：通常用1--3句说明其代表的假设或为何纳入比较，不逐个展开教材式原理。
- 核心改进算法：可展开其结构、目标函数、约束、伪代码和流程图，但每一部分必须对应真实代码或结果。
- 深度网络：重点写输入尺度、骨干输出、改动模块、损失、冻结/微调策略和决策规则；不逐层复述公开架构手册。
- 同一机制只解释一次。图已经清楚展示的层级和连接，正文只解释关键设计及其作用。
- 公式必须在后文被使用、估计、求解、验证或解释。仅用于展示知识储备的公式删除。

“一个段落加一条核心公式”是常见基线，不是机械上限；复杂度应由本题实际贡献决定。

## 标题与跨小问承接

- 标题使用读者可见的研究任务、数据动作或数学动作，如“异常值处理”“特征提取”“分布滞后模型建立”“拟合结果与误差分析”。参数来源、证据等级、结果文件定位和下游消费者属于内部清单，不直接作为正文标题。
- 后续小问继承前一问时采用增量式叙述：先说明保留的目标、数据或模型，再说明新增信息/约束及其带来的新困难，最后引出新增处理。不要重新复述整套上游方法，也不要直接以“本问采用某算法”开场。
- 公共数据章只写多问共同使用且只需解释一次的事实和处理；问题专属的标签量化、特征构造、时间重整、窗口选择和模型输入构造仍留在对应问题附近。

## 流程图位置

- 总体求解路线图通常紧跟对应问题或小问的问题分析，用于先建立阅读地图。
- 算法内部流程图放在该算法的数学结构或求解过程附近，用于说明循环、判断、更新和输出。
- 伪代码只在需要精确表达执行顺序、分支、迭代、终止或 fallback 时展开；不为满足固定版式而与流程图重复。

## 从百科式写法改为本题写法

以下皮肤病变分类示例只展示改写方法，不得迁移其中的对象、模型、数据划分或数值；其他赛题应完全替换为自身事实和证据。

不推荐：

> EfficientNet由Google于2019年提出，其核心贡献是复合缩放理论。传统卷积神经网络通常沿深度、宽度或分辨率单一维度扩展。

推荐：

> 训练集规模有限，而皮肤病变的判别线索同时包含局部纹理和整体形状。本文选用参数量较小的EfficientNet-B0作为基线骨干，并利用ImageNet预训练降低从头训练的过拟合风险；随后只通过受控消融判断BiFPN、骨干容量和输入分辨率是否带来增益。

不推荐：

> 交叉熵是一种广泛应用于分类问题的损失函数，能够衡量真实分布与预测分布之间的差异。

推荐：

> 普通交叉熵不修正七类样本数量差异，因此作为无重加权基线；温和加权交叉熵根据训练集类别频数提高小类权重，Focal Loss进一步降低易分样本的贡献。三者使用相同数据划分和训练协议，以隔离损失函数的影响。

## 段落功能审计

完成一章后，为每个自然段标记一个主要功能：

- `T`：任务或困难；
- `M`：模型、公式或实施；
- `E`：数据、表图或数值证据；
- `I`：解释、比较或机制；
- `B`：适用边界、风险或直接回答。

连续两个以上段落只有通用 `M` 而没有本题输入、参数或证据，通常属于教材式堆砌。连续多个 `T` 段则说明问题重述和问题分析可能重复。`E` 后没有 `I/B`，说明论文只报数没有完成建模解释。

## 精炼流程

1. 删除模型提出者、年份、发展史和与本题无关的排行榜数据。
2. 合并重复定义；术语在第一次出现时解释一次。
3. 把“方法可以做什么”改为“本文具体怎样做、输入输出是什么”。
4. 把形容词换成比较基准和数值，例如用“提高1.6个百分点”替代“明显提升”。
5. 将参数来源、验证规则和结果移到对应模型旁边，减少读者前后查找。
6. 渲染PDF，检查是否因删除文字造成孤立标题、大面积空白或图表失去解释。

## 版面与篇幅

一等奖样本的总页数差异很大，不能用总页数判断质量。应按信息价值分配版面：背景和通用知识从紧，核心建模、真实结果、消融、误差与结论从实。比赛有页数上限时优先删除百科内容、重复流程和装饰性图表，不压缩关键证据字号。

## 自动扫描的定位

可运行：

```powershell
python scripts/audit_paper_prose.py <论文目录或TeX文件>
```

脚本只定位长段落、长句、百科式开头和高频套话，不自动改写，也不以关键词数量判定论文好坏。逐条结合上下文判断：必要的定义保留，不能服务本题推理的内容压缩。
